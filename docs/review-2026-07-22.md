# `iracing-sdk` engineering review — 2026-07-22

## Scope

This review covers the current `iracing-sdk` crate, with emphasis on correctness,
maintainability, API design, naming, hidden bugs, and future extensibility.

At the start of the review, `HEAD`, `main`, and `origin/main` referred to the same
commit and there was no uncommitted PR delta. The findings below therefore describe
the current crate rather than regressions attributable to a particular pull request.

## Must fix

### 1. Make the Windows shared-memory boundary sound

`windows/connection.rs` exposes safe methods that perform unchecked pointer
arithmetic using offsets, lengths, and counts read from shared memory. Initial
connection validation checks only the SDK version, so malformed or transient header
values can lead to out-of-bounds pointers. Fixed-size strings are also passed to
`CStr::from_ptr`, which can read beyond their arrays when no NUL terminator is present.

Relevant code:

- `crates/iracing-sdk/src/windows/connection.rs:65`
- `crates/iracing-sdk/src/windows/connection.rs:318`
- `crates/iracing-sdk/src/windows/connection.rs:355`
- `crates/iracing-sdk/src/windows/connection.rs:379`
- `crates/iracing-sdk/src/windows/connection.rs:405`

Recommended direction:

- Record or query the mapped region length.
- Validate every offset, length, count, and computed range before dereferencing it.
- Decode fixed arrays with bounded NUL searches.
- Keep mapped-memory references inside a small, audited unsafe abstraction.
- Avoid returning shared references to externally changing mapped structures.

### 2. Return an internally consistent owned frame snapshot

`Connection::get_new_data` reads a buffer tick before and after constructing a
borrowed slice, but the caller copies that slice only after the consistency check has
finished. The producer may start rewriting the buffer during that later copy.

`LiveProvider` also selects the latest buffer again after copying the data, allowing
bytes from one frame to be labelled with a different frame's tick or session version.
`live_to_csv` follows the same split-read pattern.

Relevant code:

- `crates/iracing-sdk/src/windows/connection.rs:315`
- `crates/iracing-sdk/src/providers/live/mod.rs:130`
- `crates/iracing-sdk/src/bin/live_to_csv.rs:96`

Recommended direction: copy the frame bytes and capture the tick and session version
inside one retry loop in `Connection`. Return an owned snapshot containing all three
values so callers cannot accidentally separate data acquisition from metadata
acquisition.

### 3. Correct the throttle stream state machine

The custom throttle returns `Poll::Ready(None)` when its upstream is temporarily
`Pending` and no item is buffered. In the `Stream` contract, `None` means permanent
end-of-stream. A live `UpdateRate::Max` subscription can consequently terminate before
its first frame or after any quiet interval.

Relevant code: `crates/iracing-sdk/src/stream/throttle.rs:52`.

Recommended direction:

- Track upstream completion separately from temporary lack of data.
- Return `Poll::Pending` while waiting for a future item.
- Preserve the latest buffered item until the next permitted emission.
- Add paused-time tests using delayed and intermittent streams.

### 4. Make replay delivery lossless

The telemetry task publishes frames through a `watch` channel, which retains only the
latest value. `IbtProvider::next_frame` completes immediately, so the producer task can
consume an entire file without yielding to a subscriber. `IbtConnection` may therefore
emit only the final frame even though its example expects to write one CSV row for each
recorded frame.

Relevant code:

- `crates/iracing-sdk/src/telemetry.rs:170`
- `crates/iracing-sdk/src/connections/ibt/mod.rs:103`
- `crates/iracing-sdk/examples/disk_position_derive_connection.rs:84`

Recommended direction: use pull-based replay iteration or a backpressured channel for
recorded telemetry. Latest-wins delivery can remain an explicit live-telemetry policy,
but it should not be shared implicitly with replay.

### 5. Serialize and version session publication

Each detected session version starts an independent parsing task. An older, slower
parse can overwrite a newer result. The version is marked handled even when fetching
or parsing fails, so that version is never retried. At end-of-stream, the main task can
publish `None` before an outstanding parser later publishes `Some`.

Relevant code: `crates/iracing-sdk/src/telemetry.rs:125`.

Recommended direction:

- Serialize parsing, cancel superseded work, or tag results and discard stale versions.
- Mark a version handled only according to an explicit success/failure policy.
- Coordinate parser completion or cancellation with provider shutdown.
- Include the session version in the published session value where useful to consumers.

### 6. Remove panics from normal public API inputs

Both connection `subscribe` methods use `expect` for adapter validation. A schema that
does not support a caller's adapter therefore terminates the process rather than
returning `IRacingSDKError`. `UpdateRate::Max(0)` is also publicly constructible and can
reach a division by zero when calculating a duration.

Relevant code:

- `crates/iracing-sdk/src/connections/ibt/mod.rs:96`
- `crates/iracing-sdk/src/connections/live/mod.rs:73`
- `crates/iracing-sdk/src/types/update_rate.rs:35`

Recommended direction: make subscription creation fallible. Represent a maximum rate
with `NonZeroU32`, or validate it in a fallible constructor before creating the stream.

## Should fix

### Preserve schema invariants

`VariableSchema::validate` uses unchecked multiplication and addition when calculating
variable ranges. Public fields and derived `Deserialize` also let callers bypass
`VariableSchema::new` entirely.

Use checked arithmetic, keep invariant-bearing fields private where practical, and
validate deserialized schemas through `TryFrom` or custom deserialization.

Relevant code: `crates/iracing-sdk/src/types/schema.rs:23`.

### Preserve unknown variable types

The live connection maps every unknown SDK type discriminant to `Int32`. This hides
corruption and makes future SDK additions decode incorrectly.

Return an error for unsupported types or add an `Unknown(i32)` representation that
callers can inspect without pretending the value is an integer.

Relevant code: `crates/iracing-sdk/src/windows/connection.rs:89`.

### Use RAII during Windows connection setup

If mapping the view or opening the event fails, resources acquired earlier in
`Connection::try_connect` are not yet owned by `Connection` and can leak.

Wrap each handle or mapped view in an owning guard immediately after acquisition, then
assemble the final connection only after setup succeeds.

Relevant code: `crates/iracing-sdk/src/windows/connection.rs:180`.

### Standardize public errors

`SessionInfoParser` exposes `anyhow::Result`, whereas the rest of the SDK exposes the
structured `IRacingSDKError`. Application-oriented error erasure in a library API makes
matching and recovery harder and expands the public dependency surface.

Use the crate's `Result` alias and retain structured error variants.

Relevant code: `crates/iracing-sdk/src/schema/session/cache.rs:8`.

### Add regression coverage for delivery semantics

The current tests pass but do not exercise the failure modes above. Add tests that:

- receive exactly 12, 24, and 48 frames through `IbtConnection` for the existing fixtures;
- keep throttled streams alive while their source is temporarily pending;
- simulate session parse results completing out of order;
- verify retry behavior after session fetch or parse errors;
- reject hostile shared-memory headers before any pointer arithmetic;
- confirm frame bytes, tick, and session version come from one snapshot.

## Nice to have

### Consolidate duplicated wire structures

The C-layout header and variable representations are duplicated between
`windows/connection.rs` and `schema/header.rs`/`schema/variables.rs`. Their validation
and unknown-type behavior have already diverged. A single wire-format representation
would reduce unsafe surface area and future SDK update work.

### Express delivery policy in the API

Live telemetry is naturally latest-value and may intentionally drop stale frames.
Recorded telemetry is naturally lossless. Separate types or explicit delivery-policy
configuration would make these guarantees visible and prevent a shared implementation
from accidentally imposing live semantics on replay.

### Prefer invariant comments over narration

Comments such as “Write the row,” “Update frame counts,” and “Clean up” repeat the next
statement without explaining constraints. Prefer comments that document expansion of
array variables, shared-memory consistency requirements, or other non-obvious behavior.
