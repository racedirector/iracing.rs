# IBT parser implementation notes

These notes accompany [the IBT specification](ibt-spec.md). They describe implementation and refactor considerations, not additional format rules.

`crates/iracing-sdk/src/ibt/reader/mod.rs` validates the main and disk headers, bounds non-overlapping variable and session regions after the preamble, builds and owns the schema/session metadata, and computes `frameStart` as the greatest present metadata-region end. It requires the EOF-delimited telemetry region to contain only complete `bufLen`-sized frames and logs a warning when a positive disk record count differs from the computed count. Construction rejects malformed geometry; a source shortened after construction produces a frame-read error rather than logical EOF. The reader synthesizes returned ticks from zero-based frame indices and uses a 60 Hz fallback for time calculations when `tickRate` is nonpositive. Those are API behaviors, not wire-format facts.

The fixture generator's canonical order is narrower than the spec's offset-based reader contract. Raw wire representation and ABI tests belong to [iracing-irsdk](../crates/iracing-irsdk/src/lib.rs), including [IbtHeader](../crates/iracing-irsdk/src/ibt_header.rs) and [VariableHeader](../crates/iracing-irsdk/src/variable_header.rs). Fixture assembly and verification belong to `crates/test-fixtures/src/{generate,verify,model}.rs`. The iRacing SDK definitions and disk writer provide the upstream structure and writer behavior; capture evidence is recorded separately in [IBT observations](ibt-observations.md).
