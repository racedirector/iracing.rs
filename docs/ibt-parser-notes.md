# IBT parser implementation notes

These notes accompany [the IBT specification](ibt-spec.md). They describe implementation and refactor considerations, not additional format rules.

`crates/iracing-sdk/src/ibt/reader/mod.rs` validates the main header, bounds variable and session regions, builds the schema, and computes `frameStart` as the greatest present metadata-region end. It currently divides remaining bytes by `bufLen`, silently excludes a partial tail, and logs a warning when a positive disk record count differs from the computed count. The specification now defines that partial tail as malformed/truncated input; rejecting it is intentionally deferred to the corruption-hardening layer of the file-backed-reader stack. The reader synthesizes returned ticks from zero-based frame indices and uses a 60 Hz fallback for time calculations when `tickRate` is nonpositive. Those are API behaviors, not wire-format facts.

The fixture generator's canonical order is narrower than the spec's offset-based reader contract. The ABI tests and files establish a 112-byte main header plus a 32-byte disk sub-header. Relevant code is in `crates/iracing-sdk/src/irsdk/{header,disk_sub_header,variable_header,variable_buffer,variable_type}.rs`, `crates/iracing-sdk/src/types/{regions,session_info_buffer,schema}.rs`, and `crates/test-fixtures/src/{generate,verify,model}.rs`. The iRacing SDK definitions and disk writer provide the upstream structure and writer behavior; capture evidence is recorded separately in `docs/ibt-observations.md`.
