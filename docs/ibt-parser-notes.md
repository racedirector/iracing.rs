# IBT parser implementation notes

These notes accompany [the IBT specification](ibt-spec.md). They describe implementation and refactor considerations, not additional format rules.

`crates/iracing-sdk/src/ibt/reader/mod.rs` validates the main header, bounds variable and session regions, builds the schema, and computes `frameStart` as the greater region end. It currently divides remaining bytes by `bufLen`, silently excludes a partial tail, and logs a warning when a positive disk record count differs from the computed count. It synthesizes returned ticks from zero-based frame indices and uses a 60 Hz fallback for time calculations when `tickRate` is nonpositive. Those are API behaviors, not wire-format facts.

The `IbtFile` prototype in `crates/iracing-sdk/src/ibt/file.rs` owns file bytes and derives bounded metadata regions. It does not yet call `Header::validate_ibt`, build the schema, check metadata overlap, or count complete frames. A parsed file value could establish these invariants once and carry the validated frame start, frame size, count, raw session region, headers, and schema into the reader. Replay would then use indexed frame access while YAML decoding remains separate from binary layout parsing.

The fixture generator's canonical order is narrower than the spec's offset-based reader contract. A comment in `crates/iracing-sdk/src/ibt/format.rs` describes a 144-byte main header; the ABI tests and files establish a 112-byte main header plus a 32-byte disk sub-header. Relevant code is in `crates/iracing-sdk/src/irsdk/{header,disk_sub_header,variable_header,variable_buffer,variable_type}.rs`, `crates/iracing-sdk/src/types/{regions,session_info_buffer,schema}.rs`, and `crates/test-fixtures/src/{generate,verify,model}.rs`. The local SDK mirror at `D:/Workspace/irsdk_1_20` and an [online SDK definitions copy](https://github.com/vipoo/irsdk/blob/master/irsdk_defines.h) provide the upstream structure definitions.
